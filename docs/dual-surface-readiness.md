# Rusetat dual-surface readiness

Production domain supplied by the owner: **https://rusetatmigration.org**.
Implementation is local. Preview indexing remains off and no deployment occurred.

## Banya framework adaptation

Guide: the canonical Banya Labs `banya-agents/skills/agent-readiness-architect/SKILL.md`
at `C:/Users/sewar/repos/Banya Labs/banya-agents/skills/agent-readiness-architect/SKILL.md`.
The human surface is the existing server-built HTML, navigation, forms, search
and optional hosted chat. The machine surface exposes the same public copy and
page hierarchy in concise, deterministic formats. Both are generated by one build.

This is a static public-content site. MCP tools, agent bearer tokens, transaction
queues and new chat platforms are not needed for reading it. The machine
manifest states that there are no mutation actions or MCP endpoint. Public
enquiry forms prepare drafts; the hosted chat/assessment remains a separate
interactive service. Machine files do not claim a submission, booking, payment
or visa-decision capability and contain no staff-portal/client records.

## Images and accessible content

Informative images require non-empty, specific descriptions. The shared image
helper now fails if an image key lacks an alternative rather than falling back
to generic travel copy. Generated scenes and portraits are labelled illustrative.
The original logo retains the business-name alternative. Country flags beside
the same written country name use `alt="" aria-hidden="true"`; decorative SVG
stamps and interface icons remain hidden. Page checks distinguish intentional
decorative alternatives from missing descriptions. These checks do not replace
a complete screen-reader or WCAG audit.

## Preview and production builds

The default is `SITE_INDEXABLE=false`: canonical pages use `noindex,nofollow`,
and robots.txt disallows automatic crawling. This is a discovery preference,
not authentication or a way to protect confidential content.

For an approved public release, build with:

```powershell
$env:SITE_ORIGIN = 'https://rusetatmigration.org'
$env:SITE_BASE_PATH = ''
$env:SITE_INDEXABLE = 'true'
python scripts/build.py
npm test
```

Public mode allows search crawlers, including OAI-SearchBot, and still explicitly
blocks GPTBot training crawling. Search discovery and training are independent
controls. No claim is made about every provider's training crawler. Invalid
origins, HTTP public origins, local/demo public origins and invalid boolean
settings fail the build before files are copied. Redirects and 404s remain
noindex. HTTPS, DNS and hosting access must work on the final domain.

For GitHub Pages, set repository variables `SITE_ORIGIN` to the final origin
and `SITE_INDEXABLE` to `true` for the production deployment. Without the latter,
the workflow remains a preview. Pull requests and non-main branches always keep
indexing disabled. Configure the custom domain so Pages reports
the correct base path. A project-path robots.txt is not the domain-root robots
policy; the operator must serve the intended policy at the domain root.

Before publishing, reconcile the site's existing preview labels and outstanding
agency contact, media-rights and content checks. No production release or removal
of those content limitations was part of this change.

## Verification and visibility limits

`npm test` now includes machine-surface checks for every page, structured data,
Markdown links, alt attributes, illustrative-image labels, public/preview
settings, project paths and read-only capability claims. The deployment workflow
runs the same Python machine checks. Browser visual QA is unavailable in this
session; live server headers, CDN bot access, DNS and indexing are not verified.

After deployment, verify the live canonical URLs, robots.txt, sitemap and machine
files; check for server/CDN `X-Robots-Tag` or bot blocking; add the sitemap in
Google Search Console and Bing Webmaster Tools; monitor actual impressions and
enquiries. These require access to the real deployed site and owner accounts.

`llms.txt` is an agent convenience proposal, not a Google ranking requirement or
an instruction that forces a model to recommend this business. Discoverability
depends on accessible, accurate, useful content and external indexing. Inclusion
in chat answers or search rankings is not guaranteed.
